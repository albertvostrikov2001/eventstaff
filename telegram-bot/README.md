# Telegram-бот Юнити

Бот для работников и работодателей. Использует публичный API сайта: отдельной копии каталога нет. Поиск и каждая рассылка заново запрашивают сайт; скрытие, закрытие, изменение цены или анкеты учитываются при следующем запросе. Старые сообщения в истории Telegram автоматически не редактируются. В карточке есть ссылка на актуальную страницу, отклик и связь происходят на сайте.

## Возможности

- Выбор и смена роли: работник ищет вакансии, работодатель ищет работников.
- Специальности берутся из `GET /api/v1/catalog/categories`, города — из `/catalog/cities`.
- Фильтры: специальность, город, диапазон ставки, дата начала вакансии / дата доступности работника. Ставки сохраняют единицу оплаты из карточки, диапазон применяется к сумме без пересчёта смен в месяцы.
- Постраничный просмотр, кнопка обновления и переход на сайт.
- Добровольная подписка: каждые 12 ч, 24 ч или 7 дней от момента включения. Это интервалы, не фиксированное время суток. Пустые подборки не отправляются.
- Подписка начинается с текущего состава каталога: ранее опубликованные записи не рассылаются. Новыми считаются ранее не встречавшиеся в выбранной выдаче ID, включая впервые ставшие публичными анкеты. Редактирование записи не запускает повторное уведомление.
- До пяти новых записей в одной подборке; остальные остаются на следующие интервалы. После смены фильтров отсчёт начинается заново, после смены роли подписка выключается.
- `/stop` выключает рассылку; `/delete` удаляет настройки и подписку, но не сообщения в истории Telegram.

## Локальный запуск

Нужен Node.js 20.12+ (рекомендуется 22 LTS). Дополнительных npm-зависимостей нет.

1. Создать бота через `@BotFather` → `/newbot`.
2. Скопировать `telegram-bot/.env.example` в `telegram-bot/.env`, заполнить токен и адреса одного окружения. Файл `.env` исключён из git. Не вставлять токен в исходники или команды с видимым аргументом токена.
3. Обновить и запустить API сайта: в этой версии добавлен `/catalog/categories` и исправлено совместное применение границ даты вакансий.
4. Из корня репозитория:

```sh
node --env-file=telegram-bot/.env telegram-bot/index.mjs
```

5. Открыть бота в Telegram → `/start`, выбрать роль и фильтры, посмотреть текущие результаты, включить нужную частоту уведомлений.

Для разработки можно указать локальный API, например `http://127.0.0.1:4000/api/v1`. Ссылки в карточках должны вести на доступный пользователю сайт, а не на localhost другого компьютера.

## Production

Бот запускается отдельным процессом, не требует миграции PostgreSQL, входящего порта или webhook. Нужен исходящий HTTPS к Telegram и доступ к API сайта. Если на боте уже установлен webhook, запуск останавливается; существующий webhook автоматически не удаляется.

Для Telegram по умолчанию используется встроенный HTTPS-клиент Node.js с IPv4. На VPS с сетевыми таймаутами можно добавить `TELEGRAM_TRANSPORT=curl` в `.env`: нужен установленный `curl`. Токен передаётся ему через stdin, а не аргументы процесса. Проверка TLS-сертификата остаётся включённой в обоих вариантах.

Если DNS-адрес Telegram недоступен с сервера, curl-транспорт поддерживает `TELEGRAM_API_IPV4`: IPv4 проверенного сервера Telegram. HTTPS по-прежнему проверяет сертификат имени `api.telegram.org`; сторонний прокси не используется. При изменении доступности адреса эту настройку нужно пересмотреть.

Другой маршрут можно задать через `TELEGRAM_PROXY_URL` в закрытом `.env`: `http://`, `https://`, `socks5://` или `socks5h://`, при необходимости с логином и паролем. Включается curl-транспорт; адрес из `TELEGRAM_API_IPV4` игнорируется. SOCKS5 использует DNS прокси. Прокси применяется только к Telegram: запросы к API сайта идут напрямую. TLS-сертификат Telegram продолжает проверяться; токен не передаётся прокси открытым текстом. Адрес прокси должен предоставить владелец сервера; публичные неизвестные прокси автоматически не подбираются. После изменения `.env`: `pm2 restart unity-telegram`.

Для прямого подключения с проблемного VPS предусмотрен режим `TELEGRAM_TRANSPORT=curl` вместе с `TELEGRAM_WARMUP=1`. Сначала curl выполняет HEAD к `https://api.telegram.org/`, затем в той же TLS-сессии обращается к Bot API. Вывод HEAD отбрасывается; HTTP-статус и JSON относятся только к запросу бота. Токен отправляется только в запросе Bot API. Этот режим добавляет один короткий запрос на вызов и не требует прокси или нового сервера.

1. Доставить каталог `telegram-bot` в `/opt/unity/telegram-bot`; существующий `deploy.py` его автоматически не доставляет. Обновить API стандартным способом.
2. Создать `/opt/unity/telegram-bot/.env` на сервере. Установить `TELEGRAM_STATE_DIR=/opt/unity/telegram-bot/data`. Ограничить доступ к `.env` и каталогу данных сервисным пользователем.
3. Из `/opt/unity`:

```sh
pm2 start telegram-bot/ecosystem.config.cjs
pm2 save
pm2 logs unity-telegram
```

После обновления `.env`: `pm2 restart unity-telegram`. Проверить настройку автозапуска PM2 при перезагрузке сервера. Конфигурация рассчитана на один процесс; второй экземпляр с тем же каталогом данных блокируется. Не запускать тот же токен с другим каталогом данных или на другом сервере одновременно.

Настройки, chat ID, подписки, просмотренные в рассылках ID и offset Telegram хранятся в `data/state.json`. Сохраняются атомарной заменой файла. Каталог данных должен переживать обновления и перезапуски; включить его в резервное копирование, не заменять при деплое. Повреждённый файл не обнуляется автоматически. При сбое записи процесс завершается, чтобы не подтверждать несохранённые действия.

Рассылки проверяются примерно раз в минуту, партиями до 10 подписчиков, чтобы сохранять отзывчивость команд. При большом числе подписчиков возможна задержка: это первоначальная реализация для одного процесса, без распределённой очереди. В случае недоступности API или Telegram повторная попытка — минимум через 5 минут; ответ `429` учитывает `retry_after`, `403` выключает подписку. При неопределённом исходе сетевого запроса или аварии между отправкой и сохранением возможен повтор сообщения; строгая гарантия единственной доставки отсутствует.

## Проверка

```sh
node --test telegram-bot/bot.test.mjs
```

Интеграционные тесты API (из `packages/api`, с установленными зависимостями проекта):

```sh
node --import tsx --test src/routes/catalog/bot-integration.test.ts
```

Тесты используют подменённые Telegram/API и временные файлы. Они не отправляют реальные сообщения. Для проверки интеграции нужны токен и запущенный API с актуальным маршрутом `/categories`.

Ручной сценарий: включить подписку → опубликовать новую запись на сайте → проверить подборку после интервала; изменить цену → обновить выдачу; скрыть запись → проверить исчезновение; выполнить `/stop` → убедиться, что подборки прекращаются; перезапустить процесс → проверить сохранение фильтров и расписания. Авторизация аккаунтом сайта, персональные отклики/приглашения и редактирование анкет через Telegram в эту версию не входят.
